PeterGanuRusty

A local engine that lets AI coding agents find code in one step

PeterGanuRusty (PGR) is a command-line program that runs on the developer's own machine. An AI coding agent calls it to look things up in the code it is working on, such as where a function is defined and what calls it, and nothing leaves the machine.

How to read the numbers

Evidence
The results on this site come from one Python repository: 112 runs of a single agent in 42 cells, three runs in most of them.
Tokens and turns
A token count is all the text the model read or wrote over a task, including the conversation it reads again on every turn, and a turn is one round trip to the model.
Model classes
Model classes are named by size, the light class being the smallest.
Questions
The original questions are the three lookups used in every round; the held-out questions are a second set of three.
Status
The package is in private preview.

Every turn re-reads everything

An agent works in turns, and on each turn it reads its whole conversation again. Every extra turn pays for the same context one more time.

Two turns is the floor for a lookup: one to ask and one to answer. PGR: graph and search took 2.0 turns per task on the light class and the original questions. No index took 4.0. On the held-out questions it took 2.7 turns, and no index 4.7.

Fully correct runs over both question sets

Across both question sets and both model classes, in these runs, one agent using "PGR: graph and search" was fully correct in 12 of 12 runs, against 10 of 11 with "Our engine, first generation, with embeddings". On the held-out questions alone, 6 of 6 against 4 of 5.

Counted over four cells: the light and mid classes, on the original and the held-out questions. The held-out questions are a second set of three questions of the same three shapes, written later by the same team. The people and agents who built the engine did not see them while building it.

"Most reliable" marks the one configuration with the highest share of fully correct runs over four cells (the light and mid classes, on the original and the held-out questions), a tie going to the lower mean tokens; only configurations run at least 3 times in each of those four cells, and so measured on both question sets, were eligible, and the rule was set after the runs were known.

What it does for an agent

Finds definitions and callers in one call

An agent asks once and gets where a function is defined, its parameters and every function that calls it.

  • Searches code by meaning

    An agent describes a job in words and gets the function that does it.

  • Shows what a change touches

    Before editing, an agent sees what depends on the code it is about to change.

  • Remembers findings across sessions

    What an agent has already worked out does not have to be found again next time.

The study measures the first capability. One of its questions describes a job in words, but the runs do not show whether searching by meaning helps (see Limits on the Study page). The other two capabilities are not covered by the measurements on this site.

Results

Every method answered the same lookup questions on the same repository. A script graded the answers, and token counts are what the API reported for each request. The one exception is a planning call that several runs shared, which is charged at the mean of the measured planning calls.

The two filters below scope every chart and table on this page. A model tier is a class of model, from the lightest (C) to the strongest (A). With a keyboard, Tab reaches each chart and the arrow keys move between its marks.

In short

  • Cheapest tier, one agent, methods run at least three times, fewest tokens first: S1 Shipped: lx ask, default index: 130k tokens, 2.0 turns, 2 of 3 runs fully correct; S3 Shipped: lx ask, embeddings on: 130k tokens, 2.0 turns, 3 of 3 runs fully correct; L4 lx ask, one call: 130k tokens, 2.0 turns, 3 of 3 runs fully correct; C12 lx about + hybrid: 130k tokens, 2.0 turns, 3 of 3 runs fully correct; L3 lx + hybrid search: 130k tokens, 2.0 turns, 3 of 3 runs fully correct.
  • Two turns is the floor for this task: one to ask and one to answer. On Tier C, scout, 11 methods took exactly two turns and answered everything correctly in each of their 3 runs: S3 Shipped: lx ask, embeddings on, L4 lx ask, one call, C12 lx about + hybrid, L3 lx + hybrid search, C15 lx ask + token-goat read, C13 lx, every new command, S2 Shipped: all commands, default index, N1 lx ask, no Rust embeddings, N2 lx, every new command, no Rust embeddings, C14 lx, every new command + token-goat, C7 token-goat + semble.
  • The model tier moves cost far more than the method does. With the start-up context cached, the same no-index job cost $0.0074 on Tier C (98% correct), $0.103 on Tier B (100%) and $0.343 on Tier A (100%). Send lookups to the cheapest tier.

Each bubble is one method on one model tier. Further left costs less per run, higher answers more per million tokens, bigger answered more correctly, and colour is the model tier. A method code is printed only where there is room for it. Point at a bubble for the rest, pick a method group above, or open the table view.

Table view

Tokens per run, by method

One bar per method, one panel per model tier, all on one scale. Start-up context is the prompt an agent begins with. Every later turn re-reads everything before it, which is where the re-read tokens come from. Added is new context on later turns: tool results and the earlier output of the agent. The number at the end of a bar is the total.

Table view

Cost per run, by method and model tier

Dollars at list prices with the start-up context already cached. One row per method and one dot per tier, cheapest first on the lowest tier shown. Log scale: each gridline is ten times the one before. In the table view, cache cold prices the start-up context as written to the cache, as run is what the runs were billed, and the orchestrator column, shown where there is one, is its share of the warm cost.

Table view

Every run

One row per single run, before any averaging. Each Q column is the share of that question answered correctly.

Cache warm is the cost with the start-up context read from the cache, cache cold with it written to the cache, and as run is what this run was billed. Start-up, re-read and added are the token groups of the chart above. In the Agents column, "+ plan" marks a run that reused the shared planning call. Outside the tool policy lists commands an agent used that its method did not allow.

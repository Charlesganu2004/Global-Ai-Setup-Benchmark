token-goat hooks, off and on

token-goat can install hooks in the client. They run before and after the client's own tool calls and may rewrite what a call returns. The same prompts were run with the hooks removed and with them installed.

Each row pairs a method measured without the hooks with its twin measured while they were installed. The prompt, the repository, the index and the grading are the same. The rounds are not: every run with the hooks was made in one round, and each round's agents start from slightly different context, as the table of facts below sets out.

    What the hooks did

    A hook run is one execution of a hook for one tool call. A rewritten call is one whose result, or input, the hook replaced with its own: shortened, or with text it took for a secret swapped for a redaction marker. A note is extra context the hook added beside a result. A refused call is one the hook turned down, such as a second read of lines already read: the agent gets an error in place of the result.

    Installing them

    The hooks are an optional step of the installer. They are left out unless asked for, because token-goat is under a noncommercial licence and adds a block to every rules file.

    python INSTALL.txt --token-goat                  # every client folder in your home
python INSTALL.txt --client claude --token-goat  # one client

token-goat uninstall                             # undo, Claude Code
token-goat uninstall --codex                     # undo, Codex
token-goat uninstall --copilot                   # undo, Copilot
npm uninstall -g token-goat                      # remove the package itself

    Besides the hooks and the rules-file block, token-goat's installer adds a skill to Claude Code, trust entries for its hooks to Codex, and an MCP server entry to Copilot. The setup page and the README in the repository list each file.

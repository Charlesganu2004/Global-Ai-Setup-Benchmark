Study

How the measurements were made, what they cover and what they leave out.

What was asked

Three code-navigation questions, put to the agent in every run.

  • Who calls a functionName every function in the repository that calls a given function.
  • Where a function is definedGive the file and the line where a named function is defined, its parameter names and the functions that call it.
  • Which function does a jobGiven a described job, name the function that does it, say where it is defined and name its counterpart, the function that reverses it.

How answers were graded

Every answer was checked by a script against facts read from the repository's syntax tree, so no score depends on a person's judgement.

Each answer scores between 0 and 1. The share of answers correct is the average score. A run is fully correct when all three of its answers score full marks.

How much was run

  • RepositoryPython, 86 files, about 68,000 lines
  • Questions3, each asked in every run
  • Agents787
  • Runs402
  • Configurations tested36, of which 6 are published here
  • Runs per configuration and class1 to 6

Three ways of organising the agents were tried. Only the first feeds the leaderboard and the chart.

  • Setup 1One agent answering all three questions.
  • Setup 2Three agents, one question each, with nobody checking their answers.
  • Setup 3One agent that briefs three workers and checks what they return.

Model classes

Three classes of model, named only by size. Model names and versions are not given.

  • LightThe smallest model class, run at low reasoning effort.
  • MidA middle model class, run at medium reasoning effort.
  • TopThe largest model class, run at the highest reasoning effort.

Limits

  • One repositoryEvery result comes from one Python repository of 86 files. Other repositories may behave differently.
  • One languagePython only. Nothing here says how the configurations do on other languages.
  • Three questionsThree lookup questions of modest difficulty. Harder questions may separate the configurations more, or less.
  • Small run countsEach configuration and class was run between 1 and 6 times. A cell with one run is an example, not an average, and a difference of one turn is inside the noise.
  • Machine loadWall time depends on what else the test machine was doing. Token counts do not.
  • Cost figuresWhere a run is said to cost a multiple of another, the cost is list prices applied to the measured tokens.

What is not published

Implementation details are not published.

This site reports measured outcomes only: counts of tokens, turns and answers. It does not describe how any configuration works or how the agents were set up.
